# Security, Privacy & Responsible OSINT Review

## 1. Scope & Standards

This document reviews the security architecture, authorization controls, and responsible data collection policies implemented for the social-media intelligence and AI agents integration into `Intelligence`.

The implementation complies with:
- Multi-tenant data segregation.
- Role-Based Access Control (RBAC).
- OWASP Top 10 API Security Risks (SSRF, Injection, Broken Object-Level Authorization).
- Platform Terms of Service & Responsible OSINT guidelines.

---

## 2. Threat Modeling & Mitigation Analysis

### 2.1 Server-Side Request Forgery (SSRF) Prevention
- **Threat**: Malicious user requests passing internal network endpoints (e.g., `http://169.254.169.254/latest/meta-data` or `http://localhost:8000/admin`) via YouTube URL analysis or search inputs.
- **Mitigation**:
  - The YouTube collector strictly validates that inputs match approved YouTube URL patterns (`youtube.com/watch?v=`, `youtu.be/`, or video IDs matching `^[a-zA-Z0-9_-]{11}$`).
  - Target domains for social collectors are hardcoded to authorized public endpoints (`public.api.bsky.app`, `t.me/s/`, `reddit.com`, `mastodon.social`). Arbitrary outbound URLs provided by users are never fetched directly.

### 2.2 Prompt & Content Injection Defense
- **Threat**: Malicious social media posts containing prompt injection payloads designed to alter LLM system instructions or force data exfiltration.
- **Mitigation**:
  - Raw post content is strictly segregated in user message payload delimiters.
  - Regex citation extractors operate strictly on formal token formats (`[EV-...]`) and match against cryptographically secured database evidence IDs.
  - Output sanitization ensures no injected script or styling tags are rendered directly in the frontend DOM.

### 2.3 Multi-Tenant Isolation
- **Threat**: Cross-tenant data leakage where Tenant A views social evidence or agent syntheses generated by Tenant B.
- **Mitigation**:
  - All REST endpoints (`/api/v1/social/*` and `/api/v1/agents/*`) require authenticated user context via `Depends(get_current_user)`.
  - Evidence promotion and case lookup operations enforce tenant scoping (`tenant_id == current_user.tenant_id`).
  - Automated tests (`test_tenant_isolation.py`) continuously verify that cross-tenant accesses return `404 Not Found` or `403 Forbidden`.

### 2.4 Rate Limiting & Platform Politeness
- **Threat**: IP bans or denial-of-service against social media endpoints.
- **Mitigation**:
  - Configurable timeouts (`DEFAULT_TIMEOUT = 10.0s`).
  - Polite User-Agent headers identifying the OSINT research client.
  - Exponential backoff and graceful error handling on HTTP 429 Too Many Requests.
  - Client-side and server-side request throttling limits.

## 3. Privacy & Responsible Collection Policy

1. **Public Information Only**: Only publicly viewable information is indexed (public Bluesky posts, public Telegram channels, public Reddit threads, public Mastodon federated statuses, and public YouTube videos).
2. **No Credential Bypassing**: The system does NOT employ credential stuffing, session hijacking, CAPTCHA defeating, or private account scraping.
3. **Evidence Integrity & Provenance**: Every collected social post retains source URL, collection timestamp in UTC, author metadata, and SHA-256 content hashes to guarantee forensic auditability without altering source data.
